# 游戏插件管理与数据 v1

本库是三个独立游戏插件的编译期依赖，不是运行时插件。账号调用通过独立 `accounts` v1 服务，所有 CK、SToken 和 AuthKey 留在账号提供者。

## 管理动作

### 卡池历史、复刻记录与版本抽卡统计

`banners.query` 支持 `version`、`query`（角色/装备名）、`kind=character/weapon/all`、`date`（国服日期）与 `offset`（每页 50 项）；返回固定数据里的完整期次、出现次数和最近收录期次结束距所选日期的天数。无匹配数据明确为空，不把最近收录期次当作迄今从未复刻的证明。原神/星铁使用随包 miao 资料，绝区零使用已注明版本的 GachaClock MIT 数据；不下载或转发该数据中的图片。

`gacha.versions` 对本游戏已保存档案按固定卡池区间汇总版本/半期抽数及最高稀有度数量。先把档案标注时区转换为国服时间，再匹配区间；重叠且版本矛盾、没有覆盖的记录保留在 unclassified，不丢弃也不重复计数。按“版本更新后”推算的起点明确标为 estimated，涉及的记录数量单独报告。结果不代表官方概率或完整历史。资料列表提供分页，不静默截掉其余期次。

### 后台抽卡同步与每日同步

`gacha.task.create` 接收 `account_ref`、`role_ref`、`kind=once/daily`、`full`、`days`（1–90）、`hour`（北京时间 0–23，仅 daily）、`notify`（默认 false）和 `confirm=true`。创建原神/绝区零国服角色的有期只读委托，由宿主每分钟调度推进；不复用已结束的管理或聊天事件。每个提供者/角色只有一个后台任务，不能重复创建。星铁保持 `plugin.game_sync_unavailable`，不借后台入口绕过已知上游限制。

账号插件按原样转发官方抽卡分页，只删除凭据字段。本库逐页校验记录：每页最多 20 条，UID 与所选角色一致，游标递减，池类型与请求一致，时间与 ID 格式正确；绝区零池类型转为档案池 1/2/3/5/102/103，原神 400 归入 301；记录时区取官方 `region_time_zone`（绝区零相对 UTC+8），缺失时按区服确定。

`gacha.task.list` 查看任务进度及结果；`gacha.task.run` 接收 `ref` 与 `confirm=true`，重新校验账号权限后立即排队已有任务；过期任务须重新创建。`gacha.task.remove` 停止并移除任务，尽力撤销委托；提供者不可用时本地仍停止，未撤销的授权等待到期。默认不发送完成通知；开启通知只发给原账号所属聊天用户，发送前持久标记，不能保证进程崩溃时恰好一次通知。

每次调度最多推进三页、页间至少一秒，每页使用真实调度来源重新检查授权。日任务在北京时间设定时刻后开始，完整完成或达到重试上限后等待下一日；单次任务完成后停止执行。暂时失败退避五分钟，同一轮连续三次失败后暂停单次任务或等待日任务的下一日；认证撤销、设备验证、记录冲突及异常分页暂停任务，需明确重新运行。单个任务的状态为 `creating/waiting/running/completed/paused/expired`，失败使用稳定 `last_code` 展示。

每个任务单独保存为一个文件；一次调度在网络请求期间不占用存储锁，结束时只写一次该任务（完成通知在发送前先记下），期间任务被停止、移除或因删除档案而暂停时丢弃本次结果。删除档案会等待正在合并的分页结束。分页暂存沿用现有同步器，仅保存在内存。插件重启或暂存过期时从当前档案重新开始该轮；完成全部池后原子合并，未完成的记录不写进正式档案。读取期间导入、删除或另一同步修改档案时拒绝覆盖。删除抽卡档案先暂停对应后台任务并取消暂存；不会因重启或旧任务迟到而恢复已删除的档案。其他游戏、账号和角色的任务独立。

聊天提供 `游戏同步抽卡 [增量/全量] [UID]`（单次，有期七天）、`游戏自动同步 开启/关闭 [UID]`（每日北京时间 08:00、30 天、增量、不通知）、`游戏同步进度 [UID]` 和 `游戏停止同步 [UID]`。进度和停止只按完整聊天主体查找自己的任务，无需 CK 仍有效；群停用后也允许停止。用户须重新明确开启已过期/移除任务。界面关闭不会取消后台任务；原有管理页逐页同步仍保留为独立入口。

### 云排名与公开云面板

原神/星铁 `cloud.start/poll/cancel` 提供 ark 匿名额度、玩家角色排名及角色分布查询。`start` 需显式 `consent=true`，选择 `mode=usage/rank/distribution`，排名输入公开 `uid` 和 `character_id`，分布仅需角色；固定访问 `https://ark.ivny.cn/` 的既有路由，不发送 CK 或 QQ，不接受任意 URL/请求头。

`mode=custom` 使用 `rank/custom`，输入 `character_id`、`sort=dmg_avg/mark_score`（默认伤害）、`limit`（1–50，默认 20）及最多两个 `filters`（`op` 为 >=、=、<=、>、<、!=，`value` 为 0–6 的整数）。匿名筛选固定为命座/星魂 `cons`，不将未知筛选列或任意查询对象发送到服务。结果包含 `ranking.rows` 的公开 UID、等级、命座、装备、技能、伤害与评分；服务空榜单显示为空，不视为解析错误。

`mode=rank_panel` 输入已完成自定义榜单的本地 `ref`、零起始 `index` 和 `consent=true`。服务端从该任务取出上游查询 ID 与对应 UID，限定同游戏、有效期内且已返回的前 20 行；调用者不能自填上游查询 ID。固定调用 `rank/custom/specific`，已公开的响应 UID 必须与选中行一致；服务匿名化 UID 时保留匿名显示，并校验面板含原榜单角色，不猜测或恢复身份。`mode=panel` 输入 `uid`，调用 `panel/download`，接收其他机器人已主动上传、仍在服务十分钟有效期内的面板；不触发刷新、上传或绑定。

云面板按白名单规范化角色、等级、命座、武器、技能和装备词条，按角色选择显示；旧面板的缺失字段明确标注，未知装备资料不补零。装备词条依据随包固定 miao 元数据解释。响应身份不符、无法解析或超过响应上限时失败。公开面板不会获得账号权限，不进入本人官方面板历史、抽卡档案或账号存储，不自动上传任何本地资料。

请求使用独立后台任务，最多 8 个、25 秒上游期限、5 分钟结果保留，页面轮询并可取消；插件关闭取消全部请求。每个响应最多 2 MiB，投影后的结果最多 256 KiB；错误只展示本地固定说明。只保存内存中的公开业务结果，不将云排名当作官方认证或本地实战结论。当前匿名模式不代表具备高级筛选、OCR 或云面板上传权限，这些目标仍单独保留。

### 私聊云 UID 验证

原神/星铁提供 `游戏云验证 获取/提交/状态 UID 确认` 和 `游戏云验证 进度/取消`。仅接受 OneBot11 本人私聊，QQ 从宿主认证的事件用户取得，不接受代填 QQ；输入 UID 是待证明的公开标识，不借用 CK。无确认时只回复用途说明，不访问云服务。获取只发送 UID/游戏到 `verify/code`；提交与状态查询将本人的 QQ、UID、游戏发送到 `verify`、`verify/user`。提交会在第三方建立跨机器人关联，需用户先把获取的验证码写入游戏公开签名；不会自动修改签名或凭此授予本地账号权限。

验证使用独立异步任务并通过“进度”取回结果，绑定协议、适配器、机器人、聊天用户与游戏；管理面普通 `cloud.poll/cancel` 不能读取或取消私聊验证任务。每个用户/机器人/游戏只能同时运行一次，同一请求不自动重试；取消提交不能撤销上游已发生的关联。结果和验证码仅在内存保留五分钟，验证码的服务期限为 24 小时；插件不长期保存 QQ–UID 关联，不发后台通知。验证码不包含 CK，仅在原私聊展示。QQ 官方机器人开放 ID 不当作 QQ 号使用。

### 公共资料查询

`public.query` 接收公开 `uid` 和国服 `region`，通过账号提供者的 `public.execute` 使用所有者主动加入的公共查询池，仅查询固定 `profile` 基础公开资料。页面与“游戏公开信息 UID [区服]”明确与本人账号查询区分；没有可用公共账号/预算时返回限制状态，不偷偷借用私人账号，不授予目标 UID 账号权限。

### 游戏签到

`signin.task.create` 接收账号/角色、`hour`（北京时间 0–23）、`days`（1–90）、`notify`（是否私聊结果，默认 false）及 `confirm=true`，显式创建每日签到委托；`signin.task.list/remove` 查询/停止任务。聊天“游戏自动签到 开启/关闭 [UID]”默认每天北京时间 08:00、30 天、不主动通知。宿主每十分钟触发检查，达到设定时间后执行，按北京时间日期持久去重；过期、权限撤销、首次签到要求时暂停。每天至多尝试一次，写入前标记后崩溃可能漏一次，管理页保留未确认状态供手动查询。体力提醒与签到任务分别列出、分别退订，现有账号不会自动启用。

三游戏 `signin.status` 和 `signin.rewards` 读取所选授权角色的官方游戏签到状态与当月奖励。`signin.run` 需要 `confirm=true`，由明确的“为所选角色签到”按钮或聊天“游戏签到 [UID]”发起，账号请求使用 `write_confirmed=true`。已签到保持幂等；首次签到或验证码要求明确提示由用户在官方应用处理。单次入口不创建定时任务，每日任务需单独显式开启；游戏签到与社区米游币/云游戏任务分别处理。

### 独立模拟抽卡

原神/星铁 `simulation.status/select/draw/reset/configure` 提供独立娱乐模拟，采用固定 Miao-Yunzai/StarRail-plugin 的参考概率曲线和资料池，不声明为官方概率或当前卡池；不会消耗真实货币，也不会写入 UIGF/官方档案。管理页使用独立模拟档案，聊天按协议、适配器、机器人、会话和用户分别保存。

`select` 接收 `kind`（character/weapon/standard）、`banner_id`、`featured`、`fate_target`、`fate_limit`；角色/星铁光锥从参考池显式选目标，原神武器可取消定轨或选择 1/2 点模型。不同种类的保底独立，切换角色池保留该类计数，武器换池或更换定轨目标时清空命定值。`draw` 接收 `count=1/10` 与 `request_ref`，每抽记录卡池种类 `kind` 与抽到物品的种类 `item`（character/weapon）；最近 20 个请求重复提交不重复扣除次数，同请求改变抽数拒绝。每次全批次原子保存，跨重启保留计数、模拟获得物品及最近 200 抽。

`configure` 仅供管理页设置每个模拟档案的每日总额度 10–1000（默认 100）；国服 UTC+8 的 04:00 重置每日额度。`reset` 需要 `confirm=true`，清除模拟保底、物品和历史，保留当天已用次数及请求去重记录，不能借重置绕过额度。聊天按上游措辞抽十连：原神沿用 Yunzai 的 `十连`、`十连2`、`武器十连`、`常驻十连`、`抽卡`、`单抽` 等写法，星铁沿用 StarRail-plugin 的 `十连[角色|光锥|常驻]` 与 `抽卡`；未写武器/光锥或常驻时抽角色池，原神 `十连2` 抽该期第二位五星角色，回复由游戏插件按上游十连图绘制。另有“游戏模拟记录”“游戏重置模拟 确认”；原神另有 `定轨`，按 Yunzai 每次切换到本期下一把五星武器、最后一把之后取消，也可写武器名称或“取消”。当日额度用完时按上游措辞回复：原神列出当日五星及抽数（四个及以上只计数）和本周五星数，星铁给出该池当日抽数与五星数。

### 群内设置与本群排行

三游戏“群设置”由群管理员/群主或宿主超级管理员操作，支持本游戏在当前群启停、图片/文本回复、群内别名增删和恢复默认。群设置按协议、适配器、机器人、群 ID 分开，优先于游戏全局设置，仅作用当前游戏。设置读取一次后保留在内存，每次保存时同步更新。管理动作 `groups.list` 按 `page` 查看已保存群设置与参评数量，每页 50 群，返回 `next_page`；`groups.set` 使用完整群身份、`revision` 和 `config` 保存启停、回复方式及群别名；`groups.clear` 使用群身份和 `revision` 恢复默认并清空本地排行。版本不匹配返回 `plugin.game_group_changed`，不覆盖期间的新设置或参评记录。管理页可选当前机器人创建群设置。

群成员在群内查看单个角色面板时，插件按 miao 的群排名把该面板、装备评分与等级、计算规则默认条目的期望伤害连同 UID、昵称和查询时间记入当前群；数据来自当次查看的面板（见“本地面板与更新面板”），不接受上传。每个 UID 每个角色保留最后一次查看的条目，每群最多 500 项。聊天沿用 miao 的写法：“<角色>排名”按伤害列出前十五名，带“圣遗物/遗器/评分”时按装备评分；不写角色时列出每个角色的第一；“最强<角色>”“最高分<角色>”显示第一名的面板；“词条”“双爆”排名与上游一样没有数据。宿主超级管理员可“重置[角色]排名”，群管理员可“刷新排名”（按当前规则重算已记录的面板）和“开启/关闭排名”（关闭后仍记录，只停止查询）。原神与星铁由插件按 miao rank-profile-list 出图；绝区零上游没有面板排名，“排行 角色”按装备评分列出。管理员也可用 `groups.clear` 清空本群排行。

`game.json` 的 `query_ranks` 声明按 ZZZ-Plugin 做法由群内战绩查询组成的排名：成员在群内查询所列玩法后，插件保存该 UID 最近一次的查询结果并把 UID 加入本群对应排名，成员可用“显示/隐藏××排名”切换（不写玩法时设置全部），再次查询不改变已选的隐藏。排名命令只在群内可用，按宿主提供的群成员列表剔除已退群成员的 UID，由游戏插件按上游规则筛选当期、排序并取前十五名出图；无人上榜时回复声明的提示。战绩图末尾按上游显示本人在本群的显示/隐藏状态。`groups.clear` 同时清空这些排名。

### 固定材料与卡池资料

原神/星铁 `materials.query` 按 `query` 和可选 `weekday`（0 全部、1–7 原神轮换副本日）查询固定参考材料，返回材料来源、品质、同系列与相关角色/装备；最多 100 项并返回匹配总数。`calendar.query` 按可选 `version`、`date`（YYYY-MM-DD）筛选固定参考卡池，日期按原国服时间字符串解释，同时返回该日固定生日资料；最多 50 期。返回明确资料版本与总数，不把快照资料标记成已在线验证的当前卡池/活动，也不推断快照之外的日程。公开资料查询无需 CK。绝区零保持已有角色/装备/技能图鉴，未列出没有来源的日历或材料。

### 原神与星铁养成材料

`growth.prepare` 使用 `account_ref/role_ref/character_id` 读取官方养成详情，返回当前角色/武器等级和技能/行迹的实际编号、当前等级与上限。`growth.compute` 接收同一角色选择与显式 `plan`，通过账号服务固定的只读材料计算器查询，返回规范化材料需求及官方来源说明；不会升级角色或扣除材料。目标不得低于当前等级，缺失编号/等级不补造；当前等级范围原神 1–90、星铁 1–80。没有对应参考接口的绝区零不开放此入口。

### UID 绑定

聊天命令按 Yunzai 原神插件：“绑定uid<UID>”对本人账号的 UID 设为默认角色，其他 UID 无需 CK 由账号插件的 `uids.bind` 绑定并选用；“uid”按序号列出账号 UID 与绑定的 UID，“uid<序号>”切换，“删除uid<序号>”删除绑定的 UID（账号 UID 需用“删除ck”）。当前使用的 UID 是面板、更新面板与今日素材等命令的默认 UID；需要 CK 的查询仍使用默认账号角色。

### 本地面板与更新面板

面板按 UID 保存在插件数据目录的 `profiles/`，与上游保存玩家数据相同：“更新面板”把展柜服务或账号返回的角色并入该 UID 的面板，没有返回的角色保留；“面板”“圣遗物/遗器/评分”“伤害”先读保存的面板。尚未保存的角色，若 UID 绑定在本人账号上，就读取官方面板并保存；原神与星铁随后按 miao 的做法读取一次展柜，仍没有时回复上游的提示。

展柜来源随游戏固定为上游的默认服务：原神与绝区零为 Enka，星铁为 Mihomo 的中文解析接口。请求匿名、地址固定为 HTTPS，按服务给出的 ttl 缓存（一分钟至一天），遇到 429 后一分钟内不再请求。原神按 miao EnkaData 读取武器、圣遗物、天赋与命座，属性取 Enka 给出的最终值；星铁取 Mihomo 已合计的属性，天赋等级按 miao HomoApi 由行迹节点加上星魂加成得出；绝区零在计算脚本中运行 ZZZ-Plugin 的 Enka2Mys，得到与官方格式相同的代理人条目。展柜数据不代表本人认证，也不赋予账号权限。

聊天命令沿用上游。原神与星铁：“更新面板 [UID]”读取展柜，“米游社更新面板”读取本人账号的全部角色，“面板列表 [UID]”列出已保存的角色，“删除面板<UID>”删除面板并清除本群该 UID 的排名条目，绑定账号的用户只能删除自己的 UID，宿主超级管理员不限。绝区零：“更新面板”在 UID 绑定于本人账号时读取官方数据，否则或写“展柜”时读取 Enka，同一 UID 300 秒内只能更新一次；“面板列表”列出已保存的代理人。回复措辞由各游戏 `game.json` 的 `panels` 给出。

“圣遗物列表”（星铁为“遗器列表”）按 miao 用各角色的评分规则为已保存面板上的每件装备评分，去掉主词条是唯一有效词条的件（主词条固定的前两个部位除外），按分数列出前 28 件。

原神与星铁的“面板换装”沿用 miao ProfileChange 的写法，例如“雷神换90级5精护摩换绝缘4换天赋10 10 10”“希儿换满命换满行迹”：可替换武器（名称、等级、精炼或叠影，类型不符的原神武器换为西风系列）、其他角色或其他 UID 的整套或单件装备、套装（保留词条）、命座或星魂、天赋、等级、满行迹，或让另一角色穿这套装备。换装后的属性由固定 miao 元数据从角色、武器、装备与行迹重新计算，再评分和计算伤害；图片注明“该面板为非实际数据”并附替换命令，不登记群排名，也不保存。

原神“今日素材”按 miao 取当天的天赋书与武器材料组（凌晨四点换日，“明天”“周X”指定日期，周日直接回复全部可刷），列出用到这些材料的已保存角色与其装备的武器；本人 UID 的账号数据超过两小时未刷新时，先按 miao 从账号重新读取全部角色。

管理动作 `showcase` 接收 `uid`，读取该游戏的展柜并保存，返回本次读到的角色。

### 本地面板历史

`panel.history.list/save/get/compare/remove/export` 接收 `account_ref`、`role_ref`、`character_id`。每次通过账号服务的 `roles` 重新校验当前调用者/主体和角色，停用或撤销授权后不继续读取历史。历史属于当前账号提供者、账号、游戏角色、战斗角色的组合，不按公开 UID 合并。`save` 从官方重新读取规范化面板后保存，不接受页面上传面板；每个组合最多 20 份，超出拒绝，先由用户移除旧记录。

列表返回摘要；`get/remove/export` 使用 `ref`，`compare` 使用 `before_ref`、`after_ref`。对比展示原始属性前后值、可解析且单位相同的差值，以及等级、解锁层数、装备和技能变化；缺失属性不补零，百分数差值使用百分点。快照固定保存查询时的资料版本，不以旧快照冒充当前官方状态或游戏伤害。导出只包含游戏、UID/区服、保存时间、资料版本和业务面板，不包含账号授权引用或凭据。

### 显式体力提醒

`reminder.create` 接收授权 `account_ref`、`role_ref`、`threshold`（百分数 1–100）、`days`（1–90）。创建账号委托与每十分钟宿主任务，只私聊通知该账号所属聊天用户；游戏页面清楚显示接收者，默认不创建任何任务。`reminder.list` 返回本插件任务；`reminder.remove` 停止并移除指定 `ref`，同时尝试撤销账号委托，返回 `delegation_revoked`。账号服务暂不可用时仍停止本地任务，原委托到期失效，界面明确提示。聊天“游戏体力提醒 百分数 [UID]”默认授权 30 天；“游戏关闭提醒 [UID]”撤销当前选择的角色提醒，仅允许自己的账号。

任务按实际 `scheduler.trigger` 来源和 `task_id` 查找，不假冒聊天来源。达到阈值发送一次，只有再次观测到低于阈值才重新待发；同一持续高位不循环打扰。提醒与各类定时任务每个单独保存为一个文件，同一任务不会同时运行两次；网络请求期间不占用存储锁，只读检查在请求后写一次检查时间、待发状态与最后结果，任务在此期间被移除时不再写回。发送前持久标记已尝试，采用避免重复的策略：进程恰在标记后发送前崩溃可能漏一次提醒，不能保证网络发送的恰好一次。失败状态在管理页可见。账号授权撤销或凭据失效时暂停；上游验证错误进入至少一天退避，其他失败至少一小时退避。到期任务暂停，旧宿主调度触发仅做无操作返回，不再访问账号或发消息。

### 本地抽卡明细与统计

`gacha.history` 接收档案 `uid`、`region`，可选 `pool`、`rank`（含 `unknown`）、`query`（物品名或 ID）、`from`/`to`（档案本地日期 YYYY-MM-DD）、`offset`、`limit`（1–100，默认 50）。返回倒序 `records`、筛选 `total`、`next_offset`、字符串 `revision` 与 `analytics`。翻页必须携带首次结果的 `revision`；档案期间变化返回 `plugin.game_archive_changed`，重新从第一页读取，不混合两份快照。无效筛选返回 `plugin.game_input_invalid`。

统计只描述本地已保存且符合筛选条件的记录，包含稀有度数量、已知最高稀有度占比、按档案本地月份的数量和物品分布。存在未知稀有度时占比不输出确定值。各次最高稀有度的间隔从完整档案计算后再筛选；首个间隔为历史下界，途中未知稀有度使间隔不确定，两者均不进入完整间隔平均值。所有记录仍可能有未被识别的历史缺口，不据此推断大小保底、定轨或真实抽卡概率。原神 301/400 共享间隔；绝区零 102/103 保持独立。

`gacha.summary` 的 `rare` 增加 `uncertain`，池摘要增加 `pity_uncertain`；未知稀有度之后的间隔不再被显示为确定保底。已知最高稀有度之后重新开始确定的本地记录计数。

### 三游戏整套装备与绝区零音擎试换

绝区零补充音擎规则依据固定快照的五档效果描述，由本项目实现并标注来源。无直接伤害影响的能量、失衡、防护等效果以文字条目明确显示，不填零伤害。触发条件按结果列出的参考情境解释；缺少效果描述的占位音擎不能标为已支持。防御缩放附加伤害单独计算，暴击和元素范围不得误作用于其他技能。

`build.prepare/compare` 扩展到绝区零，使用固定 ZZZ dev 快照的 BuffManager、Calculator、角色/音擎/套装规则与静态属性计算。技能按官方 `skill_type` 与总等级映射；核心技采用 1–7 级，角色突破和音擎突破按各自参考表解释，音擎候选为 1–60 级、0–5 突破、1–5 星。缺少必需属性、技能或规则时保持 `plugin.game_build_unavailable`，不将缺失被动视为零。

`build.compare` 可选 `equipment_from_character_id`，从同一已授权账号、同一游戏角色下读取另一角色的整套圣遗物/遗器/驱动盘，作为本地候选装备。装备供体只提供完整返回的装备，不提供角色基础属性、武器或技能。请求主体、账号和角色权限仍由账号服务校验；候选装备不写回游戏，不覆盖保存的面板。候选可同时更换武器，必须把旧装备静态和战斗增益移除后重新计算；候选情境仍按原参考默认条件解释。

绝区零基准与候选分别创建计算器，避免技能缓存和 Buff 状态跨方案复用。官方显示值作为基准，前后静态属性差值来自同一固定属性模型。音擎被动、驱动盘元素加成与角色核心效果按参考路径各计算一次；结果显示实际参考增益、技能与数值。没有固定规则的音擎/套装明确列为未覆盖，不能以成功输出部分值冒充完整计算。设备验证限制仅影响真人查询验收，离线规则和合成场景可继续实施。

### 角色参考计算与武器换装

`build.compare` 可提供 `conditions` 创建自定义候选情境：`disable_character/disable_weapon/disable_equipment` 关闭对应来源的局内参考增益；`enemy_resistance` 为显式抗性百分数；`bonuses` 为所列数值增益；`team` 最多原神/星铁三名、绝区零两名互异队友，各项包含 `character_id` 和 `bonuses`。队友从本游戏固定图鉴选择，只作为用户填写增益的来源，不擅自假定队友技能等级、装备或自动套用一份通用满配增益。数值单位和范围由 `build.conditions` 返回；任意脚本、未知字段标识、非有限值及重复/同角色队友拒绝。

基准保持原参考情境，候选可仅改变条件，也可同时换装；返回候选实际采用的队伍、增益、来源开关和抗性。增益在对应计算乘区内应用，不在最终伤害上随意乘一个总系数；百分比基础属性明确使用基础值，100% 不得被当作固定 1 点。每条结果保留参考招式及默认触发说明，用户关闭来源后可自行填写实际条件。

`build.presets.list/save/remove` 管理本游戏的非敏感模拟方案。save 使用 `name`、`character_id`、`conditions` 和可选 `ref/revision`，最多 64 项；已有项必须按版本更新，移除同样核对版本。方案不含账号引用、UID、CK 或真实面板，删除账号不会隐式删除模拟方案。页面可保存/载入方案，聊天“游戏队伍计算 方案名 [UID]”从调用者自己的授权角色读取面板后应用方案。

`build.prepare` 接收 `account_ref`、`role_ref`、`character_id`，由游戏插件重新读取已授权角色，返回固定参考支持状态、当前计算输入、技能等级、兼容武器选项和计算条件。`build.compare` 接收同一账号/角色选择、`enemy_level` 与可选 `candidate_weapon`（`id`、`level`、`promote`、`refinement`），重新读取角色后计算当前配装和候选武器的技能伤害。UI 不上传面板或凭据；候选只表示本地换装试算，不修改游戏装备。基准与候选按参考条目 ID 对齐，零基准不输出变化百分比。

`build.prepare` 同时返回基准 `build`，避免初次打开时重复读取官方面板。合法的未装备状态用空 `id`、`level=0`、`promote=0`、`refinement=1` 表示，缺失官方装备字段与明确未装备分别处理；普通候选武器的突破阶段必须适用于指定等级。非伤害说明以 `kind=text`、`text` 显示，`expected=null`，不伪造为零伤害。聊天 `游戏计算 角色 [UID]` 使用同一账号校验与自动参考规则。三个游戏均开放该入口。

官方技能总等级直接用于参考倍率，避免重复叠加命座/星魂等级。星铁忆灵技能和激活行迹一并读取；装备接口缺少套装名时仅按固定资料中的准确装备 ID/名称关联。突破阶段缺失时，比较合法阶段与官方基础属性选择匹配项，基础属性明显不符则拒绝计算。

星铁强化形态依照固定参考名单及技能编号前缀识别，为计算和评分选择强化元数据并重映射行迹。官方账号查询和响应的 `character_id` 继续使用真实游戏 ID；自动结果增加 `variant=enhanced` 并在角色名标注强化形态，不把内部规则 ID 发往官方接口。

本阶段原神、星铁使用固定 miao 快照的角色、武器、套装条件和伤害规则。参考情境（例如半血、满层、特定队伍）随每条技能及增益明确展示，不推断为玩家实际战斗状态；不提供任意脚本或远程规则输入。缺失等级、武器/技能映射或必需数据返回 `plugin.game_build_unavailable`，不补造技能等级。输入非法返回 `plugin.game_build_input_invalid`。规则失败、超时或非有限结果保持明确失败状态。

参考函数随游戏程序打包，由插件内嵌的纯 Go ECMAScript 执行库运行；这是复现复杂条件的计算依赖，不加载 Yunzai 或 Node 服务。每次计算创建独立上下文，只有已筛选的游戏 DTO 和固定数学/格式化辅助函数；不暴露账号服务、文件、网络、进程或宿主动作。可复用的编译结果只读，执行受请求取消、时间与栈深约束。已实现的通用公式和动态评分保留原 Go 路径。

属性基准使用官方面板，武器换装的静态属性变化依据同一固定元数据前后重算；条件增益重新计算，避免将旧武器的战斗增益保留到候选。输出注明固定参考版本、参考情境与模拟来源。三游戏整套装备替换与绝区零规则见前节，自定义队伍与条件编辑见前述 `build.conditions`，规则收录不等同于完整真人验收。

### 挑战群榜

`challenge.schema` 返回本游戏的固定玩法、指标顺序与升降方向。聊天“游戏提交挑战 玩法 [本期/上期] [UID]”只读取发起者已授权角色的官方成绩，向当前群公开 UID、昵称及成绩快照。“游戏挑战排行 玩法 [期次] [指标] [页码]”按玩法、区服、官方期次分别排列；每页 20 项。缺失必需成绩或期次不入榜；缺失次要指标排在有值之后，不补零。快照保存 180 天，每群最多 2000 项。同分按首次提交及主体排序，不宣称官方全服排名。

“游戏退出挑战 [玩法]”删除本人在当前群的记录，账号失效和群功能关闭时仍可使用；“游戏清空挑战 [玩法]”要求群管理员身份。管理 `challenge.list` 按完整 `scope`、`kind`、可选 `season/dimension/offset` 返回分区分页及快照；`challenge.clear` 要求 `revision` 与 `confirmed=true`，可按玩法清空。管理页不能代替用户创建参评成绩。重建排序只重新整理已有指标，不借用群成员凭据刷新。


### 挑战完成提醒

`challenge.reminder.create` 接收账号选择、`kind`、该玩法 `metric`、`threshold`（0–10^14）、`hour/minute`、`weekday`（0 每日，1–7 周一至周日）、`days`（1–90）及 `confirm=true`；创建仅限该角色、固定挑战操作的只读委托。默认关闭，按北京时间在指定时刻之后五分钟内检查本期成绩。高分指标未达阈值或低值指标超过阈值才私聊账号所属用户；未提供的指标保持未知、不补零、不发送误报。同一日/周的准入在请求前持久保存；重启不补发重复通知。撤权暂停，设备验证暂停至少一天，错误不会频繁重试。

`challenge.reminder.list/remove/check` 分别列出、取消指定任务、立即查询所选角色的挑战达标状态（不发送通知）。创建管理界面可为已授权角色设置每天/每周时间和期限；聊天“游戏挑战提醒 玩法 指标 阈值 [HH:MM] [UID]”默认每日 20:00、30 天，“游戏关闭挑战提醒 [UID]”随时取消本人任务，关闭体力提醒不影响挑战提醒。全局管理停止只取消已选择的任务，不为未授权用户开启提醒。


### 月报档案与累计

`monthly.fetch` 以已授权账号角色及可选 `month` 读取一份官方月报并保存，同月更新、最多 120 个月、单份 64 KiB。客户端可依次请求官方 `optional_month` 内的月份，各次请求单独保存；中途失败保留已完成月份，明确显示部分完成，不补造已失效历史。原神仅返回月数时按查询时北京时间推定最近对应年份，标记 `year_estimated=true`。

`monthly.list/get/remove` 每次重新校验账号/角色，档案按提供者及账号角色分开。list 返回月份、保存时间、已提供收入、每种收入的覆盖月数及累计；缺失收入不当零，累计仅代表已保存月报。get 返回历史摘要；remove 使用 `month` 和档案 `revision`，过期版本拒绝删除。fetch 在请求前读取 revision，若期间档案被修改则拒绝覆盖。重启可读，不含 CK 或登录材料。


`monthly.task.create/list/remove` 提供默认关闭的每日月报收集。create 使用账号角色、`hour/minute`（北京时间）、`days`（1–90）、`confirm=true`，可选 `notify` 默认 false；每天只读取并保存官方默认月份，历史月份仍由管理页显式依次获取。调度绑定专用 `monthly` 只读委托，每天读取后写一次任务状态，失败不会覆盖已保存月份或频繁重试，删除本地任务立即停止后续收集。


### ark 凭据配置

`cloud.start` 可显式设置 `authenticated=true` 使用 ark 令牌，否则保持匿名请求。令牌由账号插件加密保存，本库不保存也拿不到令牌：授权请求通过账号服务的 `ark.request` 由账号插件代发，并在当前事件内完成后返回任务结果；匿名请求直接发送至固定 `https://ark.ivny.cn/`，不随重定向转发。未配置令牌时授权请求失败，匿名能力不受影响。


授权云查询的 `advanced_filters` 最多 16 项，字段仅来自 `cloud.filter_schema`：角色/装备等级、突破、命座、技能等级、精炼、伤害、评分、数据时间、套装及星铁各部位主词条；原神不支持部位主词条条件。比较符沿用固定六种，数值必须有限，文本最多 64 字符；高级条件要求 `authenticated=true` 且令牌已解锁。匿名 `filters` 继续仅支持最多两项命座条件。用量接口分别标注匿名或授权额度；401/403 与 429 返回独立稳定错误，令牌不因短暂限流自动删除。


### 云排名扩展

`cloud.start` 增加 `self_rank`（UID 与 1–250 个 `character_ids`）、`group_rank`（角色及 1–50 个 `uids`）、`stygian`（原神、1–50 个 UID）和 `akasha_stygian`（原神、UID 列表与明确 `version`）。只发送用户明确填写的公开查询参数。`rank` 可选择 `query=dmg/mark/all` 和 `refresh=true`；返回数组时伤害与装备排名分开展示，保留百分位。

ark 群查询按返回顺序对应请求 UID，单角色批量排名按返回顺序对应请求角色，不自行探测其他用户。Akasha 使用固定 HTTPS GET、禁重定向且永远不发送 ark 令牌；两服务结果分别标记来源，不把不同难度/赛季或算法混成一个名次。异常长度、缺失对应项和格式变化明确失败，数据未知不当零。


### 装备 OCR 与试算

`cloud.start` 的 `mode=ocr` 接收公开 HTTPS `image_url`、装备 `slot` 和 `forge`（是否识别前后两件），并要求明确外发同意。图片 URL 发给固定 `ark.ivny.cn/ocr/profilechange/gs|sr`；不接受 localhost、字面私有 IP、URL 认证或含 CK/AuthKey 字段的 URL。本地不下载图片，也不把 QQ/CK 发给 OCR 服务。结果只保留已校验装备字段和固定资料能解释的主副词条；缺失或不兼容装备保持明确失败。

`cloud.ocr.compare` 使用仍有效的 OCR 任务引用、已授权账号角色和 `character_id`，重新读取本人当前官方面板，将识别的新装备放到所选部位进行候选试算。结果标注为模拟，并展示截图的识别前后装备；不改游戏数据、本地官方历史或群榜，不宣称截图旧装备一定与当前角色相同。用户明确选择角色及部位，避免多角色相似装备时自动替换错对象。

聊天沿用 ark-plugin 的两个 OCR 入口，图片取自命令消息及其引用的消息，地址规则同上，匿名请求且不进入任务列表。“游戏ark重塑识别”（星铁为“ark重投识别”）识别第一张图片的前后两件装备，在当前 UID 已保存的面板中查找部位相同、副词条种类与数值按游戏显示精度一致的一件（星铁速度允许相差 2，同 ark-plugin），主词条相同者优先；找不到时明确回复，找到后按面板换装的方式计算换上新装备的面板。“面板换装”附带或引用截图时最多识别 6 张，按识别出的部位换上装备，命令中写明来源的部位优先。两者均为模拟结果，不保存，不登记群排名。

聊天另沿用 ark-plugin 的排名与面板交换：“游戏角色排名<角色>[UID]”请 ark 更新后查询该角色的伤害排名，“游戏总排名[UID]”按当前 UID 已保存面板的角色查询，“游戏<角色>排名统计”查询评分分布。“游戏导出面板数据”把本人账号 UID 已保存且来自官方的面板按交换格式上传，十分钟有效；“游戏导入面板数据<UID>”下载后按面板换装的方式由等级、武器、天赋、行迹与装备重新计算属性，存入该 UID 的已保存面板，来源标为 share（上游写入玩家数据后同样显示），之后的“面板”直接读取。导出与导入只允许本人账号的 UID。


### 云面板交换档案

面板交换保留 miao PlayerData 的无凭据核心格式（UID、角色、技能、命座、武器、装备词条与时间），保存到独立的“交换档案”，明确标记第三方/导入来源，不覆盖官方实时面板或其历史。所有保存、导出和上传都重新验证所选本地账号角色，云 UID 必须相同；任意公开面板仍可查看，但不会因此获得账号所有权。

`cloud.archive.list/get/remove/receive/upload` 分别读取档案摘要、单角色、按版本移除、从有效云下载结果合并、明确同意后上传已有档案至 ark 的十分钟交换服务。upload 发送 UID 和全部已保存角色业务数据，不含 QQ、CK 或账号引用。保存与删除校验 `revision`；每个角色账号最多 250 个角色、总计 4 MiB，单角色最多 32 KiB。

本地导入使用 `cloud.archive.import.start/append/finish/cancel`，start 选择已授权角色并捕获档案版本，append 每次一个已筛选角色（序号可重复但内容须一致），finish 再验授权和版本后原子合并。导出使用 `cloud.archive.export.start/read/close`：固定快照逐角色读取，每次重验授权，客户端生成同格式 JSON。传输会话最多 8 个、15 分钟到期，重启失效。浏览器只提交白名单业务字段，不发送整份未筛选原文件；后端再次筛选验证，输入未知字段忽略，凭据字段不落盘。

`cloud.archive.rank` 在同意后将所选交换角色发送给 ark 的本地面板排名接口，使用该接口约定的模拟 UID，展示时明确标记导入面板名次；不假称本人官方成绩。`cloud.archive.refresh` 在同意后请求 ark 更新已授权 UID 的云面板，仅确认请求被接受，稍后再读最新结果。

长期 `panel/data` 仅通过 OneBot11 本人私聊“游戏云面板 获取 UID 确认”调用，QQ 从真实聊天来源取得，管理页不能提供 QQ。进度/取消绑定完整聊天主体；“保存”还须匹配本地已绑定的相同 UID，合并为第三方交换档案。私聊任务不能通过管理 `cloud.poll` 或管理档案接收操作读取，不因云验证而获得本地账号权限。


`cloud.archive.capture` 读取一个本人已授权角色的官方详细面板，将其转为可交换的 miao 核心格式后按档案版本合并；可分别选取多个角色，不隐式上传。角色/武器突破优先采用官方值，缺失时复用固定参考属性匹配；技能等级扣除已知命座/星魂加成，强化形态采用参考格式中的形态编号。装备主属性和词条按固定资料转换，按官方显示值与强化次数寻找最接近的档位；显示值存在舍入，导出明确标为还原近似，不假称真实升级顺序。缺少必要数据或无合理档位时拒绝整个角色的转换，不输出补零面板。


### 社区与云游戏

`community.status/posts` 使用所选已授权 `account_ref` 读取米游币/社区任务与本游戏讨论区帖子，不要求存在游戏角色。`community.run` 使用 `step=sign/read/like/unlike/share`、必要的 `post_id` 和 `confirm=true` 执行一次明确操作，不自动重放。游戏侧只处理任务结果，SToken/CK 始终留在账号插件。

`cloudgame.status` 显示账号插件保存的最近云钱包快照；`cloudgame.sign` 明确确认后查询钱包并领取可能发放的免费时长。原神另有 `cloudgame.rewards/claim` 查看通知奖励与逐项明确确认领取。云授权在账号插件中加密配置，游戏页不接收 Token。聊天“游戏米游币 [账号序号]”“游戏社区签到 [账号序号]”“游戏云游戏状态 [账号序号]”“游戏云游戏签到 [账号序号]”分别对应状态与明确操作，普通游戏 CK 不因社区或云授权错误而标为失效。


`community.task.create/list/remove` 与 `cloudgame.task.create/list/remove` 提供显式的一次任务或每日任务：账号、北京时间时分、1–90 天期限、`once`、默认关闭的 `notify`、`confirm=true`。社区可分别选择浏览、点赞、分享及点赞后取消；计划先读状态和本游戏帖子，再逐分钟处理一步，最终重新读任务状态。每一步在发请求前持久记下尝试，失败停止本轮、不自动重放写步骤；账号授权或云 Token 不可用会暂停。一次任务完成后停止，每日任务到下个时刻开始新一轮；关闭和取消不需要 CK 仍有效。社区任务进度属于同一米游社账号，可选择常用游戏开启。


### 兑换码与资产记录

`codes.query` 匿名查询本游戏官方导航/前瞻活动的公开兑换码，最多尝试八个固定活动候选，显示来源、获取时间及上游提供的有效期；若使用固定参考日期规则估计，明确 `expiry_estimated`，不宣称当前必定可兑换。`redeem.run` 选择已授权角色与代码，需 `confirm=true`；国服保留在游戏内兑换提示，海外按固定官方接口适配。

`billing.page` 选择本人角色、类别和方向，按原神游标或星铁页码读取官方当前可提供的资产变动记录，AuthKey 不进入游戏插件。明细保持大整数 ID 字符串；记录与档位统计仅表示游戏资产变化，不能当作实际支付账单或付款金额。


`billing.sync.start/step/cancel` 分批收集所选类别及方向的当前可用记录，任务引用保留十五分钟、最多八项，每一步使用当前事件授权，重复序号返回相同进度。全量读取成功才提交到本地资产档案；过程中档案变化则拒绝覆盖。每个角色类别最多 30000 条、8 MiB，官方编号保留字符串。有编号的旧记录合并保留，无编号记录只保留本轮快照并明确覆盖说明。`billing.archive.list/get/remove` 每次重验账号角色，按月/关键词筛选与 50 条分页；统计为记录数量和官方变动数值的分类合计，不把固定档位猜测当成真实付费金额。


### 官方公开内容与订阅

`content.start/poll/cancel` 为匿名固定 HTTPS 查询提供进程内任务，最多八项，25 秒执行上限、10 分钟结果期限。`kind=codes/news/search/post/calendar`：news 按类型 1/2/3 和 last_id 翻页；search 为本游戏关键词检索；post 只接受米游社文章编号或本游戏官方文章链接，不抓取任意 URL。正文作为纯文本分段显示，原图仅保留 HTTPS 官方 CDN 链接。公开内容不使用账号凭据，不执行其中的代码。

calendar 合并官方公告列表与正文，区别公告展示时间与实际活动时间。只从明确活动时间段提取可解析日期；更新完成后、永久开放等没有确定时刻的内容保留原文及未知状态，不自动估算终止日。最多 300 条，原始公告可查看。

`content.subscription.list/remove` 管理已开启订阅；聊天“游戏订阅 公告/资讯/活动/到期 [天数]”和“游戏退订 [类型]”创建或取消本人私聊或当前群的推送，群设置要求管理员。默认关闭，1–90 天，每十五分钟检查；首次读取建立基线，不发送历史新闻。到期仅提醒有明确结束时间且在未来 24 小时内的活动；同一活动期限只尝试发送一次。基线、尝试记录与期限持久保存，发送失败也不自动重放，重启不会重复；暂停群不推送。来源异常保留旧基线。订阅到期发一次到期通知并停止；管理清理不需要账号服务在线。


### 攻略、地图与原魔数值

`guides.schema/settings` 列出固定参考的攻略来源和当前默认来源；`guides.configure` 用版本号保存默认来源。`content.start kind=guides` 按 source、角色名和 collection_offset 查询对应官方合集，保留完整帖子入口和来源。合集按固定来源内的编号选择，结果分页使用本次合集中的位置，不将第三方观点当作本地计算结论。

聊天“游戏[更新]<角色>攻略[来源序号|all]”与上游攻略命令相同：读取该来源的全部合集，取第一篇标题含角色名的帖子中最大的图片（原神与绝区零按文件大小、星铁按高度，绝区零略过 GIF 与标题中的【…本…】标签，原神第四个来源从合集长文中按“角色名】”后的图片取），加上游的缩放参数后以图片地址发送；星铁开拓者按“开拓者”与命途两词匹配，原神旅行者需写明元素。找到的地址在内存中保留一天，“更新”重新查找；all 发送前四个来源。“游戏攻略帮助”列出用法与来源序号，超级管理员以“游戏设置默认攻略<序号>”修改默认来源。

`map.query` 为原神生成固定 HTTPS 地图服务链接，只接受材料名称和地表/渊下宫/层岩地下三个地图选项；不接收自定义主机或带凭据 URL。地图服务的可用性单列，素材位置以其服务返回为准。聊天“游戏<资源>在哪里”按逍遥图鉴：名称中写渊下宫、层岩地下等时查对应地图，向 map.minigg.cn 取图后发送，内存保留最近 32 张，“刷新”“更新”重新获取；服务回复拒绝时转述其说明，连接失败时回复证书、TLS 握手、超时等具体原因。

`enemies.schema/query` 使用固定 Atlas 数值资料，原神独立展示原魔、等级、HP/ATK、来源版本及修饰因子。每个因子类别最多一个，怪物特例先于默认倍率；等级未指定时采用因子的预设等级，最后使用90级。缺失基础值、曲线或因子明确失败，不把未知当作1或0。输入选定的等级、基础值、曲线和倍率均在结果中展示。

`blueprint.read/compute` 仅原神已授权角色可用。read 获取尘歌壶分享码对应的摆设需求，compute 按所选摆设数量计算材料；CK 由账号插件持有。无有效参考接口的游戏不暴露入口。


### 上游图片素材

`artwork.status` 按 `game.json` 声明顺序返回 `sources`，每项含 `id`、`name`、`state`（`missing`、`downloading`、`ready`，或按需下载来源的 `on_demand`）、已下载的 `files` 与 `bytes`，以及可选的 `commit`、`downloaded_ms`、下载中已接收的 `received` 和上次失败的 `error`。`artwork.download` 以 `id` 在后台开始下载或更新，已在下载时不重复开始；`artwork.delete` 删除已下载的来源，下载中拒绝。三者都返回最新的 `sources`。聊天中超级管理员使用“游戏素材更新 [素材名]”开始下载，“游戏素材状态”查看进度。

每个来源是一个上游公开仓库，按声明顺序尝试其 tar.gz 地址（Atlas 先 Gitee 后 GitHub，其余为 GitHub），只保留声明路径下的图片（图鉴库另含索引文件），按仓库内相对路径存到插件数据目录的 `assets/<id>/`。下载完成后整体替换上一份，失败时保留上一份并记录原因；插件包不含第三方图片。模板以 render.image 的 `path` 资源引用这些文件，素材缺失时使用不依赖图片的样式。`game.json` 的 `pictures` 声明聊天图片取自哪些来源：`photos` 为角色照片目录（`{name}` 代表角色名，原神为 miao 的 `character-img`，旅行者取空与荧两者），“照片”、互动与戳一戳从这些目录与本地图库中该角色的图片里随机取一张；`atlas` 为图鉴库，依次查 Atlas 的 `path.json`（按文件中的模块顺序）或 `{name}` 文件路径（原神另有逍遥图鉴），“图鉴”在没有插件自绘的资料页时发送找到的图鉴图。来源尚未下载且没有可用图片时，回复中给出对应的素材更新命令。声明 `mirrors` 的来源与上游 ZZZ-Plugin 一样在出图时逐个下载所需文件并缓存，不能整体下载，可删除缓存；某个文件在所有镜像都取不到时，一小时内不再请求。

### 本地图库与角色互动

`media.upload.start/append/finish/cancel` 分批上传使用者有权使用的 PNG/JPEG/GIF/WebP 原图；每张最多4 MiB、2400万像素。start 声明标题、分类、可选资料条目、来源与使用许可，append 采用连续偏移并支持一致内容重放，finish 验证格式/尺寸和版本后原子保存。会话最多八项、十分钟到期；临时数据只在游戏进程内，关闭即取消。各游戏图库独立，最多2000项、原图总计512 MiB。

“游戏照片 角色名”“游戏图鉴图 分类 关键词”“游戏原图”读取本地素材（照片同时取下载的角色照片，原图也可取回下载的图片）；原图关联当前聊天主体与最近一次本人触发的图片，十分钟有效，不使用其他用户的图片引用。“游戏互动 关系 设置/添加/移除/列表/随机/照片/卡片 [角色名]”提供明确角色选择、列表及娱乐展示，不代表真实人物关系，也不推断缺失的性别/年龄标签。

戳一戳默认关闭，通过“游戏戳一戳 开启/关闭”选择是否参与。仅响应本机器人收到的真实通知，同一主体十秒冷却、重复事件不重发。各游戏插件互不协商：同时在多个游戏开启的用户会收到各自的回复。


### 帮助、版本和别名冲突

`help.query` 返回随本版本编译的正式命令声明、插件/资料版本、许可和最低宿主版本；聊天“游戏帮助 [关键词]”“游戏版本”使用相同声明。帮助按清单的命令分组输出，按当前群开关和操作者权限过滤，用法使用宿主下发的首个生效前缀。

自定义别名始终优先于内置名称与内置别名。`aliases.validate` 校验、规范化最多 256 个全局别名，名称不超过 64 字节、目标必须存在，并返回覆盖了内置名称的别名列表供管理员核对；群设置最多 64 个群别名，群别名优先于全局别名。未知配置字段继续忽略，此前保存的 `alias_policy` 不再生效。

### 矩阵补充操作

原神 `birthday.list/claim` 分别查询和明确领取留影叙佳期，使用本人授权角色；claim 需要 confirm，活动 Cookie 不返回游戏插件。`cards.query` 读取月谕圣牌完整收藏，群内查看“月谕圣牌”时按上游做法把本人缺少/重复卡片记入当前群的交换匹配，有效 30 天，再次查看时刷新；“月谕圣牌交换”同样登记本人，并仅列双向互补且同区服的成员，最多八项。“交换”只提供匹配，不自动赠送卡片或操作其他成员账号。


星铁 `billing.playtime` 基于本人已保存的开拓力全部变动档案和用户明确选择的自然恢复分类，按每次增加1点对应之前6分钟推算在线窗口，跨午夜拆分并合并重叠；空白不是已确认离线。结果标为估算，不作为官方在线时长。


`content.start kind=stats` 读取原神 Lelaer/Yshelper 固定公开统计，区分持有率与持有者命座分布的样本分母，保留缺失值。`statistics.teams` 使用已完成深渊统计任务和本人角色授权，重新查询本人角色详情，按参考等级/天赋权重配对不重复角色的上下半队伍；缺失字段采用参考默认1且标记。`kind=estimate` 读取固定参考作者的版本资源预估帖子，保留发布时间及观点来源，不将预估当作官方数值。

# 游戏插件管理与数据 v1

本契约描述绝区零插件的管理动作与数据。账号调用通过独立 `accounts` v1 服务，所有 CK 与 SToken 留在账号提供者；本插件只在读取聊天中的抽卡链接及“获取抽卡链接”时经手 AuthKey（见“聊天中的抽卡链接”）。

## 管理动作

### 卡池历史、复刻记录与版本抽卡统计

卡池资料与 ZZZ-Plugin 一样运行时读取 GachaClock 的绝区零历史（六秒超时，缓存一天，读取失败时沿用上次结果），按上游 processData 补上 GachaClock 缺少的 1.0 上半卡池、按结束时间排序，并为“公测开启后”“版本更新后”写出起点（后者为上一期结束次日 11:00，标为推算）。管理动作读不到时使用随包、已注明版本的 GachaClock MIT 固定快照；本插件不下载该数据中的图片。

聊天命令按 ZZZ-Plugin 的 poolHistory，四条规则依次为：“<名称>复刻记录”（复刻/卡池 + 统计/记录/历史），名称为“(五星|S级?)?(角色|代理人)”“(四星|A级?)?(角色|代理人)”“(五星|S级?)(武器|音擎)”“(四星|A级?)(武器|音擎)”时回复对应的复刻统计（各项最近一期结束至今未复刻的天数，不含进行中及未开始的），否则按上游 aliasToName 把角色名或别名换成 GachaClock 使用的名字后列出该代理人或音擎的各期卡池；“卡池”（前面可加当前、本期或当期）回复进行中的卡池、剩余天数与各卡池图片；“卡池记录”（复刻/卡池 + 统计/记录/历史）以合并转发按版本从新到旧列出全部卡池；“v<版本>[上半|下半]卡池”回复该版本或半期的卡池与图片。回复文字与上游相同，卡池图片与上游一样以图片消息段发送 GachaClock 给出的图片地址，由聊天平台获取。读取失败且没有上次结果时回复“卡池历史记录数据获取失败: 原因”。与上游不同之处：别名表以全名为键的五名代理人（如浮波柚叶）改用 GachaClock 使用的短名，否则上游查不到其记录；版本号须完整匹配，“2.1卡池”不含 2.10；上游把全部卡池的转发消息缓存一周，这里每次按当天的资料生成。

`banners.query` 支持 `version`、`query`（角色/装备名）、`kind=character/weapon/all`、`date`（国服日期）与 `offset`（每页 50 项）；返回完整期次、出现次数和最近收录期次结束距所选日期的天数。无匹配数据明确为空，不把最近收录期次当作迄今从未复刻的证明。

`calendar.query` 按可选 `version`、`date`（YYYY-MM-DD）筛选同一份卡池资料，日期按国服时间字符串解释；每页最多 50 期，返回资料版本与总数。不把快照资料标记成已在线验证的当前卡池，也不推断资料之外的日程。

`gacha.versions` 对本游戏已保存档案按卡池区间汇总版本/半期抽数及最高稀有度数量。先把档案标注时区转换为国服时间，再匹配区间；重叠且版本矛盾、没有覆盖的记录保留在 unclassified，不丢弃也不重复计数。按“版本更新后”推算的起点明确标为 estimated，涉及的记录数量单独报告。结果不代表官方概率或完整历史。资料列表提供分页，不静默截掉其余期次。

### 聊天中的抽卡链接

私聊中出现调频记录链接（含 `authkey=` 与 `nap`）时，插件按 ZZZ-Plugin 的 gachaLog 处理，不经账号插件：取出 `authkey`、`region`（默认 `prod_gf_cn`）与 `game_biz`（默认 `nap_cn`，`nap_global` 时访问海外接口），按 ZZZ-Plugin 的 getZZZGachaLink 参数直接读取官方调频记录接口，UID 取自任一频段的第一条记录，读不到时回复“未查询到uid，请检查链接是否正确”。读取按后台同步的同一校验逐页合并到该 UID 的档案，完成后回复“抽卡记录更新成功，共6个卡池”及各频段的新增与总条数。与 ZZZ-Plugin 的默认设置相同，群聊中的链接与“抽卡链接”只回复“当前群聊未开启链接刷新抽卡记录功能，请私聊发送”；本群关闭游戏功能时不处理。“抽卡链接”在私聊回复“请发送抽卡链接……”。

`authkey` 只保存在进程内存中。一个事件内读不完时，插件创建每分钟一次的临时调度任务继续读取，完成后向原聊天发送同样的回复并删除任务；每个事件的读取在事件时限前结束，届时未读完的一页由下一次触发重新读取，15 分钟内仍未读完时回复“后台读取超时，未能完成。”并删除任务。插件重启后任务不再继续，需要重新发送链接。

“获取抽卡链接”按 ZZZ-Plugin 只在私聊可用：对当前使用的 UID（须为本人账号的国服角色），经账号插件的 `gacha.link` 取得独家频段的抽卡记录链接并原样发出；国际服 UID 回复“国际服不支持此功能”，取得失败回复“authKey获取失败，请检查cookie是否过期”。

### 后台抽卡同步与每日同步

`gacha.task.create` 接收 `account_ref`、`role_ref`、`kind=once/daily`、`full`、`days`（1–90）、`hour`（北京时间 0–23，仅 daily）、`notify`（默认 false）和 `confirm=true`。创建国服角色的有期只读委托，由宿主每分钟调度推进；不复用已结束的管理或聊天事件。每个提供者/角色只有一个后台任务，不能重复创建。

账号插件按原样转发官方抽卡分页，只删除凭据字段。插件逐页校验记录：每页最多 20 条，UID 与所选角色一致，游标递减，池类型与请求一致，时间与 ID 格式正确；池类型转为档案池 1/2/3/5/102/103，记录时区取官方 `region_time_zone`（相对 UTC+8），缺失时按区服确定。

`gacha.task.list` 查看任务进度及结果；`gacha.task.run` 接收 `ref` 与 `confirm=true`，重新校验账号权限后立即排队已有任务；过期任务须重新创建。`gacha.task.remove` 停止并移除任务，同时删除其宿主调度任务，尽力撤销委托；提供者不可用时本地仍停止，未撤销的授权等待到期。默认不发送完成通知；开启通知只发给原账号所属聊天用户，发送前持久标记，不能保证进程崩溃时恰好一次通知。

每次调度在事件时限内连续推进分页，两页之间至少间隔一秒以避开米游社限流，每页使用真实调度来源重新检查授权；被时限截断的一页由下一次调度重新读取，不计为失败。日任务在北京时间设定时刻后开始，完整完成或达到重试上限后等待下一日；单次任务完成后停止执行。暂时失败退避五分钟，同一轮连续三次失败后暂停单次任务或等待日任务的下一日；认证撤销、设备验证、记录冲突及异常分页暂停任务，需明确重新运行。单个任务的状态为 `creating/waiting/running/completed/paused/expired`，失败使用稳定 `last_code` 展示。

每个任务单独保存为一个文件；一次调度在网络请求期间不占用存储锁，结束时只写一次该任务（完成通知在发送前先记下），期间任务被停止、移除或因删除档案而暂停时丢弃本次结果。删除档案会等待正在合并的分页结束。分页暂存沿用现有同步器，仅保存在内存。插件重启或暂存过期时从当前档案重新开始该轮；完成全部池后原子合并，未完成的记录不写进正式档案。读取期间导入、删除或另一同步修改档案时拒绝覆盖。删除抽卡档案先暂停对应后台任务并取消暂存；不会因重启或旧任务迟到而恢复已删除的档案。其他账号和角色的任务独立。

聊天按 ZZZ-Plugin 的“刷新抽卡记录 [UID]”（也可写更新抽卡、刷新抽卡链接等）为所选角色创建单次任务（有期七天），已有任务时重新运行；任务记下发起聊天与当时各频段条数，本轮完成后在该聊天回复上游格式的各频段新增与总数，回复前先清除记录，重启不会重发。管理页创建的任务不记录发起聊天，仍按其完成通知设置私聊。界面关闭不会取消后台任务；原有管理页逐页同步仍保留为独立入口。

### 公共资料查询

`public.query` 接收公开 `uid` 和国服 `region`，通过账号提供者的 `public.execute` 使用所有者主动加入的公共查询池，仅查询固定 `profile` 基础公开资料。页面明确与本人账号查询区分；没有可用公共账号/预算时返回限制状态，不偷偷借用私人账号，不授予目标 UID 账号权限。

### 游戏签到

`signin.task.create` 接收账号/角色、`hour`（北京时间 0–23）、`days`（1–90）、`notify`（是否私聊结果，默认 false）及 `confirm=true`，显式创建每日签到委托；`signin.task.list/remove` 查询/停止任务。聊天“自动签到 开启/关闭 [UID]”默认每天北京时间 08:00、30 天、不主动通知。宿主每十分钟触发检查，达到设定时间后执行，按北京时间日期持久去重；过期、权限撤销、首次签到要求时暂停。每天至多尝试一次，写入前标记后崩溃可能漏一次，管理页保留未确认状态供手动查询。体力提醒与签到任务分别列出、分别退订，现有账号不会自动启用。

`signin.status` 和 `signin.rewards` 读取所选授权角色的官方游戏签到状态与当月奖励。`signin.run` 需要 `confirm=true`，由明确的“为所选角色签到”按钮或聊天“签到 [UID]”发起，账号请求使用 `write_confirmed=true`。已签到保持幂等；首次签到或验证码要求明确提示由用户在官方应用处理。单次入口不创建定时任务，每日任务需单独显式开启；游戏签到与社区米游币/云游戏任务分别处理。

### 群内设置与本群排行

“群设置”由群管理员/群主或宿主超级管理员操作，支持本游戏在当前群启停、图片/文本回复、群内别名增删和恢复默认。群设置按协议、适配器、机器人、群 ID 分开，优先于游戏全局设置，仅作用于本游戏。设置读取一次后保留在内存，每次保存时同步更新。管理动作 `groups.list` 按 `page` 查看已保存群设置与参评数量，每页 50 群，返回 `next_page`；`groups.set` 使用完整群身份、`revision` 和 `config` 保存启停、回复方式及群别名；`groups.clear` 使用群身份和 `revision` 恢复默认并清空本地排行。版本不匹配返回 `plugin.game_group_changed`，不覆盖期间的新设置或参评记录。管理页可选当前机器人创建群设置。

`game.json` 的 `query_ranks` 声明按 ZZZ-Plugin 做法由群内战绩查询组成的排名：成员在群内查询所列玩法后，插件保存该 UID 最近一次的查询结果并把 UID 加入本群对应排名，成员可用“显示/隐藏××排名”切换（不写玩法时设置全部），再次查询不改变已选的隐藏。排名命令只在群内可用，按宿主提供的群成员列表剔除已退群成员的 UID，由插件按上游规则筛选当期、排序并取前十五名出图；无人上榜时回复声明的提示。战绩图末尾按上游显示本人在本群的显示/隐藏状态。

插件配置 `group_rank_enabled`（默认 true）对应上游的 `rank.allow_group`，由超级管理员以“开启/关闭群内<式舆|危局|临界…>排名”修改，写哪种玩法都作用于全部群与全部排名，回复“绝区零群内深渊排名功能已设置为: 开启/关闭”。关闭时排名命令回复 `query_ranks` 声明的 `closed`（“当前群…排名功能已关闭！”）；群内查询战绩仍加入本群排名，但不保存该次记录，与上游相同；显示/隐藏不受影响。超级管理员在群内以“重置/清空<玩法>排名”清空本群该玩法的排名成员，玩法同上游处理函数只含式舆防卫战、危局强袭战与临界推演及其别名；危局与绝境共用一份排名，一并清空。上游此命令删除的键与成员数据不符、实际不清除任何数据，这里有意按其本意清除；已保存的各 UID 记录不受影响。

ZZZ-Plugin 没有面板排名；本插件另把群成员在群内查看的单个角色面板的装备评分连同角色、UID 与昵称记入当前群，数据来自当次查看的面板（见“本地面板与更新面板”），不接受上传。每个 UID 每个角色保留最后一次查看的条目，每群最多 500 项。“排行 角色”按装备评分列出该角色前十五名，不写角色时列出每个角色的第一。`groups.clear` 同时清空这些排行与上述排名。

### UID 绑定

聊天命令沿用 Yunzai 原神插件的写法：“绑定uid<UID>”（也可写“绑定<UID>”）对本人账号的 UID 设为默认角色，其他 UID 无需 CK 由账号插件的 `uids.bind` 绑定并选用；“uid”按序号列出账号 UID 与绑定的 UID，“uid<序号>”切换，“删除uid<序号>”删除绑定的 UID（账号 UID 需用“删除ck”）。当前使用的 UID 是面板与更新面板等命令的默认 UID；需要 CK 的查询仍使用默认账号角色。

命令没有写 UID 而 @ 了他人时，与上游相同改读被 @ 用户当前使用的 UID（经账号插件的 `uids.current` 取得），只读取不需要账号的资料：已保存的抽卡记录、面板与展柜；需要账号的查询仍只用本人账号，不使用对方的账号。被 @ 的用户没有可用 UID 时回复“对方尚未绑定uid”。@ 本机器人不算 @ 他人。

体力、战绩、月报等以账号查询的命令，命令词之后只接 UID（6–12 位数字），查询本人账号中该 UID 的角色；接其他内容时与上游规则以命令词结尾一样，不属于这条命令，不作回应。挑战的期数与月报的月份只按上游写在命令词中（如“上期深渊”“月报上月”），命令后的数字或文字不当作期数或月份。

“绑定设备”“解绑设备”与超级管理员的“设置默认设备”经账号插件的 `device.bind`、`device.unbind`、`device.default` 处理：本插件只转发命令并回复上游文案，设备信息由账号插件在随后的消息中接收并加密保存，从不经过本插件。与上游一样，私聊与群聊都可使用：“绑定设备”回复“为UID <UID>绑定设备，请发送设备信息(建议私聊发送)，或者发送“取消”取消绑定”。按上游先取 UID 的顺序：没有账号（`plugin.account_not_found`）或 `device.bind` 未返回 UID（所绑定账号没有绝区零角色）时，本人没有正在使用的 UID 则回复上游的“uid为空……”，否则没有账号回复“尚未绑定cookie，请先绑定cookie，或者扫码登录”，账号没有绝区零角色回复“未绑定UID”；国际服角色绑定时回复“国际服不需要绑定设备”，解绑时与上游一样不作回应。“绑定设备帮助”按上游以合并转发发送（转发不可用时作为普通消息发送），方法二附设备信息工具的下载链接，取插件配置 `device_download_url`，默认为上游 config.url 的默认值。

### 本地面板与更新面板

面板按 UID 保存在插件数据目录的 `profiles/`，与上游保存玩家数据相同：“更新面板”把账号或展柜返回的代理人并入该 UID 的面板，没有返回的代理人保留；“面板”“评分”“伤害”先读保存的面板。尚未保存的代理人，若 UID 绑定在本人账号上，就读取官方面板并保存，否则回复上游的提示。“练度统计”与 ZZZ-Plugin 的 proficiency 一样只读该 UID 保存的面板，不逐个读取官方详情；没有保存的面板时回复“未找到面板数据，请先%更新面板 或 %更新展柜面板”。

展柜来源为 ZZZ-Plugin 的默认服务 Enka。请求匿名、地址固定为 HTTPS，按服务给出的 ttl 缓存（一分钟至一天），遇到 429 后一分钟内不再请求。计算脚本中运行 ZZZ-Plugin 的 Enka2Mys，得到与官方格式相同的代理人条目。展柜数据不代表本人认证，也不赋予账号权限。

聊天命令沿用 ZZZ-Plugin：“更新面板”在 UID 绑定于本人账号时读取官方数据，否则或写“更新展柜面板”时读取 Enka，同一 UID 在插件配置 `panel_refresh_interval` 秒内只能更新一次（默认 60，取自上游 defSet 的 panel.interval，取代此前固定的 300 秒；0 为不限制），超级管理员以“刷新面板间隔N”（0–1000）修改；“面板列表”列出已保存的代理人。回复措辞由 `game.json` 的 `panels` 给出。读取官方数据时与 ZZZ-Plugin 的 getAvatarInfoList 相同：先读取角色列表（`characters`），再每次请求一个角色的详情（`character`），两次请求之间等待插件配置 `panel_role_interval` 毫秒（默认 3000，取自上游 defSet 的 panel.roleInterval，小于 100 时按 100；超级管理员以“刷新角色间隔N”（100–10000）修改，回复与上游相同）。全部角色读完后才保存并回复面板列表；任一角色读取失败时与上游一样回复“面板列表更新失败……”，已读到的不保存。命令开始后 40 秒内读不完的部分，先在该事件内经账号插件为这个角色创建有效期一天的 `character` 委托（委托属于发起的聊天用户，同一用户对同一角色的续读共用一项委托，再次续读时更新），再由每分钟一次的临时调度任务按同一间隔继续读取，完成后向原聊天回复；每个事件（发起的聊天事件或一次调度触发）的请求在事件时限前结束，届时仍未得到回复的角色由下一次触发重新读取，一小时内仍未读完时按上游格式回复“面板列表更新失败……后台读取超时，未能完成。”并删除任务；读取期间同一用户再次更新该角色的面板时回复“面板列表正在更新中，请稍后再试”。插件重启后未完成的更新不再继续，需要重新发送。

自定义面板图按 ZZZ-Plugin：超级管理员发送“上传/添加<角色>面板图（或角色图）”时，读取本条消息的图片，没有时读取所引用消息的图片及其中合并转发消息的图片，校验为 PNG/JPEG/GIF/WebP、每张不超过 5 MB 后保存到数据目录 `panel-images/<角色ID>/`，回复成功与失败张数；图片按上传先后编号。任何人可用“获取/查看<角色>面板图[页码]”以合并转发每页查看五张及“ID：n”，“删除<角色>面板图<ID,ID…>”（超级管理员，ID 以逗号、顿号或空格分隔）按 ID 删除。与上游规则相同，页码须紧接命令词，上传、查看命令之后另有内容时，以及删除没有写 ID 时，都不属于这些命令，不作回应。出面板图时该角色有自定义图片则随机选用一张作为立绘，否则使用默认立绘；之后十分钟内本人在同一聊天发送“原图”发送该立绘。

管理动作 `showcase` 接收 `uid`，读取展柜并保存，返回本次读到的代理人。

### 本地面板历史

`panel.history.list/save/get/compare/remove/export` 接收 `account_ref`、`role_ref`、`character_id`。每次通过账号服务的 `roles` 重新校验当前调用者/主体和角色，停用或撤销授权后不继续读取历史。历史属于当前账号提供者、账号、游戏角色、战斗角色的组合，不按公开 UID 合并。`save` 从官方重新读取规范化面板后保存，不接受页面上传面板；每个组合最多 20 份，超出拒绝，先由用户移除旧记录。

列表返回摘要；`get/remove/export` 使用 `ref`，`compare` 使用 `before_ref`、`after_ref`。对比展示原始属性前后值、可解析且单位相同的差值，以及等级、影画层数、装备和技能变化；缺失属性不补零，百分数差值使用百分点。快照固定保存查询时的资料版本，不以旧快照冒充当前官方状态或游戏伤害。导出只包含游戏、UID/区服、保存时间、资料版本和业务面板，不包含账号授权引用或凭据。

### 显式体力提醒

`reminder.create` 接收授权 `account_ref`、`role_ref`、`threshold`（百分数 1–100）、`days`（1–90）。创建账号委托与每十分钟宿主任务，只私聊通知该账号所属聊天用户；游戏页面清楚显示接收者，默认不创建任何任务。`reminder.list` 返回本插件任务；`reminder.remove` 停止并移除指定 `ref`，同时尝试撤销账号委托，返回 `delegation_revoked`。账号服务暂不可用时仍停止本地任务，原委托到期失效，界面明确提示。上游没有体力推送命令，聊天中不提供。

任务按实际 `scheduler.trigger` 来源和 `task_id` 查找，不假冒聊天来源。达到阈值发送一次，只有再次观测到低于阈值才重新待发；同一持续高位不循环打扰。提醒与各类定时任务每个单独保存为一个文件，同一任务不会同时运行两次；网络请求期间不占用存储锁，只读检查在请求后写一次检查时间、待发状态与最后结果，任务在此期间被移除时不再写回。发送前持久标记已尝试，采用避免重复的策略：进程恰在标记后发送前崩溃可能漏一次提醒，不能保证网络发送的恰好一次。失败状态在管理页可见。账号授权撤销或凭据失效时暂停；上游验证错误进入至少一天退避，其他失败至少一小时退避。到期任务暂停，旧宿主调度触发仅做无操作返回，不再访问账号或发消息。用户或管理页移除提醒、定时任务、后台同步或群推送时，在同一事件中删除其宿主调度任务；触发时找不到已保存任务的调度任务在该次触发中删除自身。每次调度触发（提醒、定时任务与群推送）的处理在事件时限内结束，时限到时仍未得到回复的读取或发送按失败处理，之后不再发起请求。

### 本地抽卡明细与统计

`gacha.history` 接收档案 `uid`、`region`，可选 `pool`、`rank`（含 `unknown`）、`query`（物品名或 ID）、`from`/`to`（档案本地日期 YYYY-MM-DD）、`offset`、`limit`（1–100，默认 50）。返回倒序 `records`、筛选 `total`、`next_offset`、字符串 `revision` 与 `analytics`。翻页必须携带首次结果的 `revision`；档案期间变化返回 `plugin.game_archive_changed`，重新从第一页读取，不混合两份快照。无效筛选返回 `plugin.game_input_invalid`。

统计只描述本地已保存且符合筛选条件的记录，包含稀有度数量、已知最高稀有度占比、按档案本地月份的数量和物品分布。存在未知稀有度时占比不输出确定值。各次最高稀有度的间隔从完整档案计算后再筛选；首个间隔为历史下界，途中未知稀有度使间隔不确定，两者均不进入完整间隔平均值。所有记录仍可能有未被识别的历史缺口，不据此推断保底或真实抽卡概率。重映与回响频段（102/103）各自独立计算间隔。

`gacha.summary` 的 `rare` 增加 `uncertain`，池摘要增加 `pity_uncertain`；未知稀有度之后的间隔不再被显示为确定保底。已知最高稀有度之后重新开始确定的本地记录计数。

### 整套驱动盘与音擎试换

补充音擎规则依据固定快照的五档效果描述，由本项目实现并标注来源。无直接伤害影响的能量、失衡、防护等效果以文字条目明确显示，不填零伤害。触发条件按结果列出的参考情境解释；缺少效果描述的占位音擎不能标为已支持。防御缩放附加伤害单独计算，暴击和元素范围不得误作用于其他技能。

`build.prepare/compare` 使用固定 ZZZ-Plugin dev 快照的 BuffManager、Calculator、角色/音擎/套装规则与静态属性计算。技能按官方 `skill_type` 与总等级映射；核心技采用 1–7 级，角色突破和音擎突破按各自参考表解释，音擎候选为 1–60 级、0–5 突破、1–5 星。缺少必需属性、技能或规则时保持 `plugin.game_build_unavailable`，不将缺失被动视为零。

`build.compare` 可选 `equipment_from_character_id`，从同一已授权账号、同一游戏角色下读取另一代理人的整套驱动盘，作为本地候选装备。装备供体只提供完整返回的驱动盘，不提供代理人基础属性、音擎或技能。请求主体、账号和角色权限仍由账号服务校验；候选装备不写回游戏，不覆盖保存的面板。候选可同时更换音擎，必须把旧装备静态和战斗增益移除后重新计算；候选情境仍按原参考默认条件解释。

基准与候选分别创建计算器，避免技能缓存和 Buff 状态跨方案复用。官方显示值作为基准，前后静态属性差值来自同一固定属性模型。音擎被动、驱动盘元素加成与角色核心效果按参考路径各计算一次；结果显示实际参考增益、技能与数值。没有固定规则的音擎/套装明确列为未覆盖，不能以成功输出部分值冒充完整计算。设备验证限制仅影响真人查询验收，离线规则和合成场景可继续实施。

### 伤害计算与自定义条件

`build.compare` 可提供 `conditions` 创建自定义候选情境：`disable_character/disable_weapon/disable_equipment` 关闭对应来源的局内参考增益；`enemy_resistance` 为显式抗性百分数；`bonuses` 为所列数值增益；`team` 最多两名互异队友，各项包含 `character_id` 和 `bonuses`。队友从本游戏固定图鉴选择，只作为用户填写增益的来源，不擅自假定队友技能等级、装备或自动套用一份通用满配增益。数值单位和范围由 `build.conditions` 返回；任意脚本、未知字段标识、非有限值及重复/同角色队友拒绝。

基准保持原参考情境，候选可仅改变条件，也可同时换装；返回候选实际采用的队伍、增益、来源开关和抗性。增益在对应计算乘区内应用，不在最终伤害上随意乘一个总系数；百分比基础属性明确使用基础值，100% 不得被当作固定 1 点。每条结果保留参考招式及默认触发说明，用户关闭来源后可自行填写实际条件。

`build.presets.list/save/remove` 管理本游戏的非敏感模拟方案。save 使用 `name`、`character_id`、`conditions` 和可选 `ref/revision`，最多 64 项；已有项必须按版本更新，移除同样核对版本。方案不含账号引用、UID、CK 或真实面板，删除账号不会隐式删除模拟方案。

`build.prepare` 接收 `account_ref`、`role_ref`、`character_id`，由插件重新读取已授权角色，返回固定参考支持状态、当前计算输入、技能等级、兼容音擎选项和计算条件。`build.compare` 接收同一账号/角色选择、`enemy_level` 与可选 `candidate_weapon`（`id`、`level`、`promote`、`refinement`），重新读取角色后计算当前配装和候选音擎的技能伤害。UI 不上传面板或凭据；候选只表示本地换装试算，不修改游戏装备。基准与候选按参考条目 ID 对齐，零基准不输出变化百分比。

`build.prepare` 同时返回基准 `build`，避免初次打开时重复读取官方面板。合法的未装备状态用空 `id`、`level=0`、`promote=0`、`refinement=1` 表示，缺失官方装备字段与明确未装备分别处理；普通候选音擎的突破阶段必须适用于指定等级。非伤害说明以 `kind=text`、`text` 显示，`expected=null`，不伪造为零伤害。

聊天“<角色>伤害[序号] [UID]”按 ZZZ-Plugin 的 damage：读取该代理人的面板（见“本地面板与更新面板”）后，把保存的官方条目构造成上游 `ZZZAvatarInfo`，经 `avatar_calc` 计算各技能伤害，再以 `calc_sub_differences` 与 `calc_main_differences` 计算置换单位副词条、主词条后所选技能的期望伤害变化，出 panel/damage 图，图中列出各技能暴击与期望伤害、所选技能的乘区与生效增益。序号选第几个技能，0 为第一个，超出时取最后一个（上游只判断大于技能数，写最后一个之后的序号时没有伤害可画，这里一并取最后一个）；不写序号时取差异计算所用的技能（标为主要技能者，否则期望伤害最高者）。只使用上游已有的音擎与驱动盘效果，上文的补充音擎规则不参与。名字不是角色时回复“角色X不存在，请确保角色名称/别称存在”，没有面板时回复“暂无角色X面板数据，请先%更新面板”，角色没有伤害规则（包括规则无法载入）时回复“暂无角色X的伤害计算”，规则中出错的技能或增益与上游一样略过；没有 UID 时回复上游 getUID 的“uid为空……”。与面板图相同，之后十分钟内本人在同一聊天发送“原图”发送图中的立绘。“<角色>面板”图末尾的伤害统计按 ZZZ-Plugin 的 panel/card 取自同一计算：`avatar_calc` 的各技能暴击与期望伤害，以及 `calc_showInPanel_buffs` 给出的、角色规则标为在面板显示的增益及其上限，同样不含补充音擎规则；计算失败时面板照常回复，不显示伤害统计。

官方技能总等级直接用于参考倍率，避免重复叠加影画等级。突破阶段缺失时，比较合法阶段与官方基础属性选择匹配项，基础属性明显不符则拒绝计算。

参考情境（例如满层、特定队伍）随每条技能及增益明确展示，不推断为玩家实际战斗状态；不提供任意脚本或远程规则输入。缺失等级、音擎/技能映射或必需数据返回 `plugin.game_build_unavailable`，不补造技能等级。输入非法返回 `plugin.game_build_input_invalid`。规则失败、超时或非有限结果保持明确失败状态。

参考函数随插件程序打包，由插件内嵌的纯 Go ECMAScript 执行库运行；这是复现复杂条件的计算依赖，不加载 Yunzai 或 Node 服务。每次计算创建独立上下文，只有已筛选的游戏 DTO 和固定数学/格式化辅助函数；不暴露账号服务、文件、网络、进程或宿主动作。可复用的编译结果只读，执行受请求取消、时间与栈深约束。

属性基准使用官方面板，音擎换装的静态属性变化依据同一固定元数据前后重算；条件增益重新计算，避免将旧音擎的战斗增益保留到候选。输出注明固定参考版本、参考情境与模拟来源。规则收录不等同于完整真人验收。

### 挑战完成提醒

`challenge.schema` 返回本游戏的固定玩法、指标顺序与升降方向。`challenge.reminder.create` 接收账号选择、`kind`、该玩法 `metric`、`threshold`（0–10^14）、`hour/minute`、`weekday`（0 每日，1–7 周一至周日）、`days`（1–90）及 `confirm=true`；创建仅限该角色、固定挑战操作的只读委托。默认关闭，按北京时间在指定时刻之后五分钟内检查本期成绩。高分指标未达阈值或低值指标超过阈值才私聊账号所属用户；未提供的指标保持未知、不补零、不发送误报。同一日/周的准入在请求前持久保存；重启不补发重复通知。撤权暂停，设备验证暂停至少一天，错误不会频繁重试。

`challenge.reminder.list/remove/check` 分别列出、取消指定任务、立即查询所选角色的挑战达标状态（不发送通知）。创建管理界面可为已授权角色设置每天/每周时间和期限；聊天“挑战提醒 玩法 指标 阈值 [时间] [UID]”开启 30 天的提醒，玩法与指标可写名称，时间写作 HH:MM、每日20时30分或每周一20时（后两种同 ZZZ-Plugin 的提醒时间），默认每日 20:00；不带参数时列出全部玩法与指标。“挑战提醒状态 [UID]”列出本人各项提醒的目标、时间、期限与上次结果，“关闭挑战提醒 [UID]”随时取消本人任务。全局管理停止只取消已选择的任务，不为未授权用户开启提醒。

式舆防卫战的指标 `s_layers`（S评级层数）按上游 remind.ts 计算：第五层评价以 S 开头计 1 层，第一至四层评价为 S 的各计 1 层；从较高层开始挑战而跳过的低层，在起始层为 S 时一并计入（从第四层开始计 4 层，从第三层开始另计 2 层，从第二层开始另计 1 层）。阈值 1–5 表示至少这些层为 S，阈值 6 表示五层都为 S 且第五层为 S+。

“开启挑战提醒 [UID]”按 ZZZ-Plugin 为本人角色创建一个 `pair` 任务，同时检查式舆防卫战（`s_layers`，阈值在 `threshold`）与危局强袭战（星数，阈值在 `deadly_threshold`）。任务在同一 task_id 下为 `zzz.challenge` 与 `zzz.deadly` 各持一份 30 天只读委托（`delegation_ref` 与 `deadly_delegation_ref`），创建时任一委托或调度失败都撤销已建的委托并删除任务，移除时撤销两份委托。每人只有一个此类任务：已在运行时回复“提醒已开启，请勿重复操作”，已到期或暂停的旧任务在重新开启时替换。到点时按各自委托读取两项，阈值为 0 的一项不读、两项都为 0 时不读；未达阈值的项与上游一样合成一条“【式舆/危局挑战提醒】”私聊，行文同上游（S评级层数、第五层评价、统计周期与刷新剩余、星数），读取失败的一项写作“<玩法>查询失败: <原因>”，两项都读取失败时按上文规则退避或暂停。“关闭挑战提醒”不带 UID 时关闭本人全部挑战提醒，回复“提醒功能已关闭”或“提醒功能尚未开启”。

阈值与时间优先取本人设置，没有时取插件配置中的全局值：`challenge_remind_time`（默认“每日20时”）、`challenge_abyss_level`（0–6，默认 5）、`challenge_deadly_stars`（0–9，默认 6），越界时回到默认值。本人以“设置式舆阈值N”（也可写“设置防卫战阈值”）、“设置危局阈值N”“设置个人提醒时间<每日20时30分|每周六20时>”“重置个人提醒时间”修改，本人设置保存在数据目录 `challenge-preferences.json`；超级管理员以“设置全局式舆阈值N”“设置全局危局阈值N”“设置全局提醒时间…”修改全局值，“个人提醒状态”“全局提醒时间”查看。本人或全局设置变化（含管理页修改配置）时，已开启任务的阈值与下次检查时间随之调整。上游要求分钟为整十，因为它每十分钟整点比对时间；这里每五分钟调度、到点后的第一次调度即检查，因此不限制分钟。

插件配置 `challenge_remind_enabled`（默认 true）是上游的全局开关，由超级管理员以“开启/关闭全局挑战提醒”修改。它只作用于“开启挑战提醒”的任务：关闭时这些任务到点不读取、记为 `plugin.game_remind_disabled`，也不能开启新的，个人阈值与时间命令回复“当前未启用防卫战/危局挑战提醒功能”；聊天与管理页创建的其他挑战提醒不受影响。“查询挑战状态 [UID]”不受开关限制，以本人账号立即读取两项并按本人或全局阈值列出全部状态行，不发送通知、不创建任务。本插件不检查是否为机器人好友。

### 月报档案与累计

聊天“月报”（也可写菲林、邦布券、收入、monthly）后可紧接 ZZZ-Plugin 的月份写法，如“月报2025年3月”“月报上月”：不写年份或早于 2023 年时为今年，只写年份、0 月或尚未到来的月份读取官方默认月份，超过 12 的月份回复日期错误。“上月”为上一个月；上游把“上”按数字换算得到无效值而总是退回默认月份，这里按其本意修正。月份须紧接命令词，命令后的内容不当作月份，按“UID 绑定”中命令后的 UID 处理。

`monthly.fetch` 以已授权账号角色及可选 `month` 读取一份官方月报并保存，同月更新、最多 120 个月、单份 64 KiB。客户端可依次请求官方 `optional_month` 内的月份，各次请求单独保存；中途失败保留已完成月份，明确显示部分完成，不补造已失效历史。

`monthly.list/get/remove` 每次重新校验账号/角色，档案按提供者及账号角色分开。list 返回月份、保存时间、已提供收入、每种收入的覆盖月数及累计；缺失收入不当零，累计仅代表已保存月报。get 返回历史摘要；remove 使用 `month` 和档案 `revision`，过期版本拒绝删除。fetch 在请求前读取 revision，若期间档案被修改则拒绝覆盖。重启可读，不含 CK 或登录材料。

`monthly.task.create/list/remove` 提供默认关闭的每日月报收集。create 使用账号角色、`hour/minute`（北京时间）、`days`（1–90）、`confirm=true`，可选 `notify` 默认 false；每天只读取并保存官方默认月份，历史月份仍由管理页显式依次获取。调度绑定专用 `monthly` 只读委托，每天读取后写一次任务状态，失败不会覆盖已保存月份或频繁重试，删除本地任务立即停止后续收集。

### 社区与云游戏

`community.status/posts` 使用所选已授权 `account_ref` 读取米游币/社区任务与本游戏讨论区帖子，不要求存在游戏角色。`community.run` 使用 `step=sign/read/like/unlike/share`、必要的 `post_id` 和 `confirm=true` 执行一次明确操作，不自动重放。插件只处理任务结果，SToken/CK 始终留在账号插件。

`cloudgame.status` 显示账号插件保存的最近云绝区零钱包快照；`cloudgame.sign` 明确确认后查询钱包并领取可能发放的免费时长。云授权在账号插件中加密配置，游戏页不接收 Token。聊天“米游币查询”“米游社绝区零签到”“云游戏状态 [账号序号]”“云游戏签到 [账号序号]”分别对应状态与明确操作，普通游戏 CK 不因社区或云授权错误而标为失效。

`community.task.create/list/remove` 与 `cloudgame.task.create/list/remove` 提供显式的一次任务或每日任务：账号、北京时间时分、1–90 天期限、`once`、默认关闭的 `notify`、`confirm=true`。社区可分别选择浏览、点赞、分享及点赞后取消；计划先读状态和本游戏帖子，再逐分钟处理一步，最终重新读任务状态。每一步在发请求前持久记下尝试，失败停止本轮、不自动重放写步骤；账号授权或云 Token 不可用会暂停。一次任务完成后停止，每日任务到下个时刻开始新一轮；关闭和取消不需要 CK 仍有效。聊天“社区任务 一次/每天 签到/全部 [账号序号]”“云游戏任务 一次/每天 [账号序号]”开启，“关闭社区任务”“关闭云游戏任务”停止，“社区任务进度”列出本人各项任务的账号、执行时间、本轮步骤进度、今日还可获得的米游币、下次执行与到期时间。

### 兑换码

`codes.query` 匿名查询本游戏官方导航/前瞻活动的公开兑换码，最多尝试八个固定活动候选，显示来源、获取时间及上游提供的有效期；若使用固定参考日期规则估计，明确 `expiry_estimated`，不宣称当前必定可兑换。`redeem.run` 选择已授权角色与代码，需 `confirm=true`；国服保留在游戏内兑换提示，海外按固定官方接口适配。

### 官方公开内容与群推送

`content.start/poll/cancel` 为匿名固定 HTTPS 查询提供进程内任务，最多八项，25 秒执行上限、10 分钟结果期限。`kind=codes/news/search/post/calendar/estimate/guides`：news 按类型 1/2/3 和 last_id 翻页；search 为本游戏关键词检索；post 只接受米游社文章编号或本游戏官方文章链接，不抓取任意 URL；estimate 读取固定参考作者的版本资源预估帖子，保留发布时间及观点来源，不将预估当作官方数值；guides 见“攻略”。正文作为纯文本分段显示，原图仅保留 HTTPS 官方 CDN 链接。公开内容不使用账号凭据，不执行其中的代码。

calendar 合并官方公告列表与正文，区别公告展示时间与实际活动时间。只从明确活动时间段提取可解析日期；更新完成后、永久开放等没有确定时刻的内容保留原文及未知状态，不自动估算终止日。最多 300 条，原始公告可查看。

`content.subscription.list/remove` 列出与移除各群的推送，条目为 `{ref, owner, group_id, kinds, sent, last_code}`，`kinds` 取 `announce`、`info`；移除时同时删除该群的调度任务。推送按 Yunzai 米游社推送：群管理员或超级管理员在群里发送“开启/关闭公告推送”“开启/关闭资讯推送”，私聊回复“推送请在群聊中设置”。每群一个每五分钟的调度任务：取开启类别的最新十条，按帖子编号从小到大推送一条创建于两小时内、标题不含上游屏蔽词且十小时内未推送给该群的帖子（先记录再发送，发送失败不重放），附“绝区零公告推送：标题”一行按 mysNews 出图。上游的活动到期预警只有原神与星铁。超级管理员“推送公告/推送资讯”立即检查全部群。暂停的群与机器人不在线时不推送。

### 攻略

`guides.schema/settings` 列出固定参考的攻略来源和当前设置；`guides.configure` 用版本号保存 `default_source`（来源序号，或 `"0"` 表示上游的 all，即前几个来源的合集），可选 `forward_count`（all 显示的来源个数，1–7，省略时保留原值，未设置时为上游默认的 4）。`content.start kind=guides` 按 source、角色名和 collection_offset 查询对应官方合集，保留完整帖子入口和来源。合集按固定来源内的编号选择，结果分页使用本次合集中的位置，不将第三方观点当作本地计算结论。

聊天“[更新]<角色>攻略[来源序号|all]”与 ZZZ-Plugin 攻略命令相同：读取该来源的全部合集，取第一篇标题含角色名的帖子中按文件大小最大的图片（略过 GIF 与标题中的【…本…】标签），加上游的缩放参数后以图片地址发送。找到的地址在内存中保留一天，“更新”重新查找；all 或 0（以及默认来源为 0 时不写序号）发送前 `forward_count` 个来源。“攻略帮助”列出用法与来源序号，超级管理员以“设置默认攻略<序号|all>”修改默认来源，以“设置所有攻略显示个数N”修改 `forward_count`；两条命令缺少参数时与上游一样不作回应。

### 上游图片素材

`artwork.status` 按 `game.json` 声明顺序返回 `sources`，每项含 `id`、`name`、`state`（`missing`、`downloading`、`ready`（已下载）、`bundled`（使用插件包随附的文件），或按需下载来源的 `on_demand`）、已下载或随附的 `files` 与 `bytes`，以及可选的 `commit`、`downloaded_ms`、下载中已接收的 `received` 和上次失败的 `error`。`artwork.download` 以 `id` 在后台开始下载或更新，已在下载时不重复开始；`artwork.delete` 删除已下载的来源，下载中拒绝。三者都返回最新的 `sources`。聊天中超级管理员使用“素材更新 [素材名]”开始下载，“素材状态”查看进度。

每个来源是一个上游公开仓库，按声明顺序尝试其 tar.gz 地址（Atlas 先 Gitee 后 GitHub，其余为 GitHub），只保留声明路径下的图片（图鉴库另含索引文件），按仓库内相对路径存到插件数据目录的 `assets/<id>/`。下载完成后整体替换上一份，失败时保留上一份并记录原因。插件包在 `assets/<id>/` 随附模板用到的文件，取自与内置资料相同的上游固定提交，由 `scripts/bundle-artwork.py` 生成；来源未下载时状态为 `bundled`，下载的同名文件优先于随附文件，删除下载后恢复使用随附文件。图鉴库与按需下载的来源不随附。模板以 render.image 的 `path` 资源引用这些文件，素材缺失时使用不依赖图片的样式。`game.json` 的 `pictures` 声明聊天图片取自哪些来源：`atlas` 为图鉴库，按 Atlas 的做法依次查已下载图鉴库 `path.json` 中的模块（按文件中的顺序）。每个模块按规则决定是否回答这句话：`rules` 以模块名给出 Atlas `rule_default/<模块>.yaml` 的条件与规则词，未列出的模块用 `config`（未声明时为 Atlas 默认的条件 3、规则词“图鉴”）；条件 0、1 原样回答，3 去掉规则词后回答，2、4、5 只在含规则词时去掉规则词后回答（聊天命令总在前缀之后）。剩下的名称先按库中 `othername/<模块>.yaml` 的别名换算为键，找不到时再用插件别名对应的角色或物品全名，发送第一个找到的图片。本游戏默认规则为条件 3、规则词“图鉴”，`material for role` 为条件 4、规则词“突破/材料/素材/培养”，`角色攻略` 为条件 3、规则词“图鉴/攻略0/攻略/指南”。“<名称>图鉴”在没有插件自绘的资料页时发送找到的图鉴图；其他命令都不匹配的词（如“艾莲”“深海访客”）由兜底命令同样查找，找不到时不作回应。来源尚未下载且没有可用图片时，回复中给出对应的素材更新命令。声明 `mirrors` 的来源与 ZZZ-Plugin 一样在出图时逐个下载所需文件并缓存，可删除缓存；某个文件在所有镜像都取不到时，一小时内不再请求。

超级管理员的“下载全部资源/下载所有资源”在后台开始下载全部仓库来源，并按 ZZZ-Plugin 为映射表中的每个代理人、音擎、驱动盘套装与邦布预先下载按需来源中模板使用的文件：立绘、方形头像、练度头像、套装图、音擎图、邦布方形头像与意象影画图（上游的圆形立绘与 Nanoka 资料文件没有模板使用，不下载）；邦布 ID 取自随包的 `BangbooId2Data.json`。已缓存的文件计为成功。事件内做不完的部分由每分钟一次的临时调度任务继续，同一时间只运行一个，完成后向原聊天回复上游格式的各类总数、成功与失败；每个事件的下载在事件时限前结束，届时未完成的一批由下一次触发重新下载（已缓存的计为成功），两小时内仍未完成时按已下载的部分回复同样的总数；插件重启后未完成的部分不再继续。“删除全部资源/删除所有资源”与上游一样只删除按需来源的缓存，仓库来源的下载与随包文件保留。

“<角色>突破/材料/素材/培养”按上述规则由图鉴库的 `material for role` 模块按角色名与别名查找并发送图片（Atlas 的角色培养材料图；此模块只回答含这些词的话，“图鉴”不查它）；图鉴库未下载时对可识别的角色给出素材更新命令，其余情况不作回应。

### 帮助、版本和别名冲突

`help.query` 返回随本版本编译的正式命令声明、插件/资料版本、许可和最低宿主版本；聊天“帮助 [关键词]”“版本”使用相同声明。帮助按清单的命令分组输出，按当前群开关和操作者权限过滤，用法使用宿主下发的首个生效前缀。

自定义别名始终优先于内置名称与内置别名。`aliases.validate` 校验、规范化最多 256 个全局别名，名称不超过 64 字节、目标必须存在，并返回覆盖了内置名称的别名列表供管理员核对；群设置最多 64 个群别名，群别名优先于全局别名。未知配置字段继续忽略，此前保存的 `alias_policy` 不再生效。
